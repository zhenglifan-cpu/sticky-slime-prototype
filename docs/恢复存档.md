# 恢复存档 — 从运行时日志提取地图数据并持久化

> 适用场景：在预览模式下编辑地图并保存到栏位后，需要将编辑结果写入 `GameConfig.lua` 使其成为默认地图。
>
> 背景：WASM 环境下本地文件存储在页面刷新后丢失，云存储（clientCloud）在预览模式不可用，因此需要从运行时日志中提取数据。

---

## 整体流程

```
预览模式编辑地图
  ↓
点击"保存地图" → 选择栏位（如栏位2）
  ↓  保存时自动调用 MapEditor.SaveToLog() + TerrainEditor.ExportToLog()
  ↓  数据通过 print() 输出到引擎运行时日志
  ↓
从日志文件提取导出数据
  ↓
对比 GameConfig.lua 默认值，识别实际变更
  ↓
将变更写入 GameConfig.lua
  ↓
构建验证
```

---

## 第一步：定位日志文件

运行时日志位于：

```
/opt/log/dev/
├── user_script.log          → 用户脚本 print() 输出（主要数据源）
├── engine.log               → 引擎日志
├── server_user_script.log   → 服务端脚本日志
└── server_engine.log        → 服务端引擎日志
```

**关键文件**：`user_script.log`（实际文件名含版本号，如 `Web(Win32)_p_ep7d_1.0.0_user_script.log`，有符号链接 `user_script.log` 指向它）。

---

## 第二步：定位目标栏位的导出数据

### 2.1 查找导出标记

```bash
grep -n "MAP EDITOR EXPORT\|TERRAIN EDITOR EXPORT\|TERRAIN DATA" /opt/log/dev/user_script.log
```

输出示例：
```
54:  === MAP EDITOR EXPORT START ===
109: === MAP EDITOR EXPORT END ===
2046:=== TERRAIN EDITOR EXPORT START ===
3887:=== TERRAIN EDITOR EXPORT END ===
```

每次保存会产生**两组**导出（MAP + TERRAIN），按时间戳区分不同栏位。

### 2.2 确认栏位时间戳

```bash
grep -n "SaveToSlot\|slot\|栏位" /opt/log/dev/user_script.log | grep -i "save\|成功"
```

根据时间戳（如 `15_19_15`）匹配对应的导出数据块。

---

## 第三步：提取障碍物数据（Obstacles）

### 3.1 提取 MAP EDITOR 导出

```bash
# 找到第 N 次导出的行范围（示例：第2次 = 栏位2）
sed -n '1990,2045p' /opt/log/dev/user_script.log
```

导出格式为可直接粘贴的 Lua 代码：

```lua
Obstacles = {
    { pos = Vector3(3, 0, 10), scale = Vector3(2.5, 2.5, 3),
      name = "Cabin", modelKey = "Cabin", modelScale = 3.7,
      modelRotation = Quaternion(0, 17, 0) },
    -- ...
}
```

### 3.2 注意 modelRotation 格式

`SaveToLog` 输出 Euler 角格式 `Quaternion(pitch, yaw, roll)`，而 `GameConfig.lua` 中使用轴角格式：

| 日志格式 | GameConfig 等效写法 | 含义 |
|---------|-------------------|------|
| `Quaternion(0, 17, 0)` | `Quaternion(17, Vector3.UP)` | yaw 17 度 |
| `Quaternion(90, 0, 0)` | `Quaternion(90, Vector3.RIGHT)` | pitch 90 度 |

建议写入 GameConfig 时使用**轴角格式**保持风格一致。

---

## 第四步：提取装饰物数据（Decorations）

`MapEditor.SaveToLog()` **只导出 Obstacles，不导出 Decorations**。

装饰物编辑记录需要从日志中的操作行提取：

```bash
grep "装饰\|decoration\|Ext_" /opt/log/dev/user_script.log | grep "缩放确认\|移动确认\|旋转确认\|删除"
```

输出示例：
```
[MapEditor] 缩放确认(装饰): Ext_TreeTall_9 -> 6.70
```

根据这些操作记录，手动更新 `GameConfig.Exterior.Decorations` 中对应条目。

---

## 第五步：提取地形数据（TerrainData）

```bash
# 查看地形导出的头部和统计信息
sed -n '2046,2060p' /opt/log/dev/user_script.log
```

地形导出格式：
```lua
TerrainData = {
    blocked = {
        { x = -16, z = -14 },
        -- ... (可能有上千条)
    },
    target = {
        { x = 13, z = 3 },
        -- ...
    },
}
```

**通常不需要手动持久化地形数据** — 地形网格在运行时由 `TerrainEditor` 根据障碍物和围栏位置自动生成。只有在手动绘制了自定义地形（非由障碍物自动计算）时才需要单独保存。

---

## 第六步：对比并写入 GameConfig.lua

### 6.1 对比策略

不要盲目替换整个数组 — 逐条对比日志导出与 `GameConfig.lua` 中的默认值，只修改**实际发生变化**的条目。

对比要素：
- `pos` — 位置是否移动
- `scale` — 碰撞尺寸是否改变
- `modelScale` — 视觉缩放是否改变
- `modelRotation` — 是否新增/修改了旋转
- 条目增减 — 是否新增/删除了障碍物

### 6.2 修改示例

本次恢复的实际变更：

| 文件 | 物件 | 字段 | 原值 | 新值 |
|------|------|------|------|------|
| GameConfig.lua | Cabin (Obstacles) | modelScale | 1.25 | 3.7 |
| GameConfig.lua | Cabin (Obstacles) | modelRotation | (无) | Quaternion(17, Vector3.UP) |
| GameConfig.lua | Ext_TreeTall_9 (Decorations) | modelScale | 3.4 | 6.7 |

### 6.3 构建验证

修改完成后必须构建：
```
调用 UrhoX MCP build 工具 → 确认构建成功 → 预览验证
```

## 关键文件清单

| 文件 | 用途 |
|------|------|
| `/workspace/scripts/config/GameConfig.lua` | 地图默认配置（修改目标） |
| `/workspace/scripts/MapEditor.lua` | `SaveToLog()` — 导出 Obstacles 为 Lua 代码 |
| `/workspace/scripts/TerrainEditor.lua` | `ExportToLog()` — 导出地形网格数据 |
| `/workspace/scripts/MapCloudSave.lua` | 栏位存档的序列化/反序列化逻辑 |
| `/workspace/scripts/ClientPreviewUI.lua` | 保存按钮 UI（触发 SaveToLog + ExportToLog） |
| `/opt/log/dev/user_script.log` | 运行时日志（数据提取源） |

## 常见问题

**Q: 日志文件不存在或为空？**
日志在每次构建+预览运行后生成。如果没有运行过游戏，日志目录可能为空。

**Q: 有多次导出，如何区分栏位？**
按时间戳对应。每次点击栏位保存按钮会先输出 `MAP EDITOR EXPORT`，紧接着输出 `TERRAIN EDITOR EXPORT`。同一时间戳的两组数据属于同一次保存。

**Q: 装饰物的编辑记录找不到？**
装饰物编辑不会整体导出，需要从日志中的逐条操作记录（缩放确认/移动确认/旋转确认/删除）中还原最终状态。如果操作较多，建议改进 `SaveToLog` 使其同时导出 Decorations。

**Q: 为什么不直接保存 JSON 到文件系统？**
WASM 沙箱环境下，`File` API 写入的数据在页面刷新后丢失。`clientCloud` 在多人预览模式下不可用。`print()` 输出到引擎日志是当前唯一可靠的数据导出通道。
